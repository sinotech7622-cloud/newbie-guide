# 園區及城鄉發展部｜新人冒險指南

Technology Park & Regional Development Dept.

GitHub Pages（免費託管網頁）＋ Google 表單與試算表版本。全程不需要寫程式，也不需要 Apps Script。

---

## 架構一覽

```
新人 ──(送出)──► 新人進度回報／技術諮詢申請／面談回覆 表單 ──► 試算表（不公開）
管理者 ──(輸入管理密碼後發布)──► 後台更新 表單 ──► 試算表「後台更新」（不公開）
                                                       │ 公式排除密碼欄
                                                       ▼
網站 ◄──(讀取)── 試算表「後台資料」（發布到網路的 CSV）
```

| 項目 | 放在哪裡 | 誰看得到 |
|---|---|---|
| 網站本體（遊戲、任務、音樂、證書） | GitHub Pages | 任何拿到網址的人 |
| 管理者專區 | 同一個網站，網址後加 `#admin`，選單中不會出現 | 知道網址的人（發布資料需要管理密碼） |
| 新人進度、技術諮詢、面談回覆 | 試算表中的表單回覆工作表 | 只有試算表的共用者 |
| 後台更新紀錄（含管理密碼） | 試算表「後台更新」工作表 | 只有試算表的共用者 |
| 任務內容、網站設定、面談通知、諮詢回覆 | 試算表「後台資料」工作表（發布到網路） | 任何知道發布網址的人 |

**運作方式**
- **管理者發布**：在管理者專區按「發布到網站」，網站會把資料送到「後台更新」表單。
- **密碼驗證**：表單用「規則運算式」檢查管理密碼，密碼不對的資料會被 Google 拒收。
- **網站讀取**：網站只讀取「後台資料」工作表，這個工作表用公式從「後台更新」取出資料並排除密碼欄，所以密碼不會被公開。

## 一、把網站放上 GitHub Pages

1. 登入 [GitHub](https://github.com)，沒有帳號請先免費註冊。建議用部門共用的帳號。
2. 右上角「＋ → New repository」。
   - 名稱例如 `newbie-guide`。
   - 選擇 **Public**。GitHub 免費方案只有公開的儲存庫能使用 Pages。
   - 按「Create repository」。
3. 點「uploading an existing file」，把 `index.html`、`config.js`（和 `.nojekyll`）拖進去，按「Commit changes」。
4. 到「Settings → Pages」。
   - 「Source」選「Deploy from a branch」。
   - 「Branch」選 `main`、`/ (root)`。
   - 按「Save」。
5. 等 1–2 分鐘，頁面上方會出現網址，例如 `https://帳號.github.io/newbie-guide/`。
   - 管理者專區網址：`https://帳號.github.io/newbie-guide/#admin`

這時網站已經可以遊玩，只是還沒連上資料。

## 二、建立試算表與四張表單

建議用部門共用的 Google 帳號操作。

### 2-1 建立試算表
到 Google 雲端硬碟新增試算表，命名為「新人冒險指南資料庫」，**不要公開分享**。

### 2-2 建立四張表單
到 [Google 表單](https://forms.google.com) 建立以下四張表單。題目順序請照表，題型用「簡答」或「段落」。除了「管理密碼」以外，都**不要設成必填**。

| 1 | 新人代碼 | 簡答 | `code` |
| 2 | 名字 | 簡答 | `name` |
| 3 | 組別 | 簡答 | `group` |
| 4 | 等級 | 簡答 | `level` |
| 5 | 完成進度 | 簡答 | `progress` |
| 6 | 結業日期 | 簡答 | `awarded` |
| 7 | 詳細資料 | 段落 | `detail` |

| 7 | 問題說明 | 段落 | `detail` |

**③ 面談回覆**

|---|---|---|---|
| 1 | 通知編號 | 簡答 | `notice` |
| 2 | 新人代碼 | 簡答 | `code` |

| 3 | 編號 | 簡答 | `id` |

| 6 | 操作者 | 簡答 | `by` |

### 2-3 四張表單都要做的設定
1. **允許不登入也能回覆**：到「設定 → 回覆」確認以下三項。
   - 「收集電子郵件地址」選「不收集」。
   - 「限制每人只能回覆 1 次」關閉。
   - 公司 Google Workspace 帳號的「限制只有（網域）的使用者可以回覆」要**關閉**。
2. **連結到試算表**：到「回覆」分頁，按「連結至試算表 → 選取現有的試算表」，選「新人冒險指南資料庫」。
   - 試算表會多出「表單回應 N」工作表，請依序改名為：「**進度回報**」、「**技術諮詢**」、「**面談回覆**」、「**後台更新**」。
3. **（技術諮詢表單）開啟新回應通知**：在「回覆」分頁按「⋮ → 收到新回應時透過電子郵件通知」。
   - 請把總長加為這張表單的協作者，並讓總長自己也開啟這個選項。

### 2-4 設定管理密碼（後台更新表單）
**請先完成第五節的「取得預先填入的連結」後，再做這一步。**

1. 打開「後台更新」表單，點「管理密碼」這一題。
2. 開啟右下角的「必填」。
3. 按「⋮ → 回應驗證」，選「規則運算式」→「符合模式」。
4. 模式填入 `^你的密碼$`，例如 `^Tpd2026SecretKey$`。
   - 建議只用英文字母和數字，至少 12 碼。
   - 不要使用個人常用密碼。
5. 錯誤訊息可以填「密碼錯誤」。

之後要換密碼，直接修改這裡的模式即可，網站和 GitHub 都不用改。

## 三、建立並發布「後台資料」工作表

1. **建立工作表**：在試算表新增一個工作表，命名為「**後台資料**」。
2. **貼上公式**：在 A1 貼上下面的公式，它會取出後台更新紀錄，並排除第 B 欄的管理密碼。
   ```
   =QUERY('後台更新'!A:G, "select A, C, D, E, F, G where C is not null", 1)
   ```
3. **發布到網路**：選「檔案 → 共用 → 發布到網路」。
   1. 展開下方的「**發布的內容與設定**」，取消「整份文件」，**只勾選「後台資料」**，按「開始發布」。
   2. 在上方「連結」區塊，左邊選「後台資料」，右邊選「**逗號分隔值 (.csv)**」，複製網址。

> ⚠ 只能發布「後台資料」。「後台更新」工作表含有管理密碼，其他回覆工作表含有新人資料，都不可以發布。

## 四、建立新人名冊（不要發布）

1. **建立工作表**：新增工作表「新人名冊」，在第一列依序輸入以下標題：

   | 欄 | A | B | C | D | E | F | G | H | I |
   |---|---|---|---|---|---|---|---|---|---|
   | 標題 | 時間戳記 | 新人代碼 | 名字 | 組別 | 等級 | 完成進度 | 結業日期 | 詳細資料 | 員工編號 |

2. **貼上名冊公式**：在 A2 貼上下面的公式，就會列出每位新人最新的一筆進度。
   ```
   =SORTN(SORT('進度回報'!A2:I, 1, FALSE), 9^9, 2, 2, TRUE)
   ```
3. **（選用）統計各組人數**：在任一空白儲存格貼上：
   ```
   =QUERY('新人名冊'!A2:I, "select D, count(B) where B is not null group by D label D '組別', count(B) '人數'", 0)
   ```

## 五、產生並上傳 config.js

1. **開啟管理者專區**：打開 `https://帳號.github.io/newbie-guide/#admin`，切到「設定小幫手」。
2. **取得四張表單的預先填入連結**：每張表單都做一次。
   1. 在表單編輯頁按右上「⋮ → 取得預先填入的連結」。
   2. 每一題填入上表的「代號」，例如管理密碼填 `pass`、類型填 `type`。
   3. 按「取得連結 → 複製連結」。**不要勾選縮短網址**。
   4. 貼到小幫手中對應的欄位，看到「✓ 已對應 N 個欄位」就代表成功。
3. **完成密碼設定**：四張表單都取得連結後，回到第 2-4 節替「管理密碼」加上必填與驗證。
4. **貼上 CSV 網址**：把第三節複製的「後台資料」網址，貼到「② 發布到網路的後台資料工作表」。
5. **（選填）填入常用連結**：填入試算表與表單的網址。
6. **下載並上傳**：按「下載 config.js」，到 GitHub 儲存庫選「Add file → Upload files」上傳（取代舊檔），按「Commit changes」。
7. **確認連線**：等 1–2 分鐘，重新整理管理者專區（Ctrl＋F5），到「連線狀態」逐一確認：
   - 四張表單都顯示「已設定」，「後台資料」顯示「正常」。
   - 按一次**錯誤的**密碼，再按「測試後台更新」。10 分鐘內應該**不會**生效，「後台更新」工作表也不會多出資料，這代表密碼驗證有作用。
   - 按「更換管理密碼」輸入正確密碼，再按「測試後台更新」。1–5 分鐘內上方「發布狀態」應該顯示「已生效」。
   - 新人用的三張表單各按一次「送出測試」，到試算表確認有沒有多一列，確認後刪除即可。

## 日常管理

### 進入管理者專區
1. 打開網站網址並在後面加上 `#admin`。網站選單中沒有入口，請把網址加入書籤。
2. 右上角填入「操作者名稱」，按「輸入管理密碼」。
   - 密碼只暫存在這個瀏覽器分頁，關閉後要重新輸入。
3. 每次按「發布到網站」後，上方「發布狀態」會自動追蹤，通常 1–5 分鐘內顯示「已生效」，所有新人就會看到更新。

### 項目管理（五大項目的任務內容）
- 分頁上方可以切換：新進相關、常見問題、各項申請、員工福利、智慧存摺。
- **可以編輯的內容**：
  - 項目介紹
  - 章節：新增、改名、排序、刪除
  - 任務：新增、編輯、排序、移到其他章節、刪除
- **任務編輯器**：所見即所得，有小標、粗體、清單、連結、路徑標籤、提示框、警告框。
- **草稿**：會自動存在這台電腦。
- **預覽**：「在這台電腦預覽」可以先回地圖看效果，只有你看得到，看完按左下角「結束預覽」。
- **發布**：確認後按「發布到網站」。
- **備份**：「匯出 CSV（備份）」可以另存目前的內容。

### 網站設定
可以修改首頁公告、村長名稱、總長稱呼、年度目標點數、組別清單、傳送門連結，改完按「發布到網站」。

### 面談通知
1. 到試算表的「新人名冊」複製新人代碼。
2. 在「面談通知」分頁填入代碼（可以一次多位）、標題、時間、地點、內容，按「發布通知」。
3. 新人會在「村長的家」看到通知，地圖上的建築也會亮起「！」。
4. 新人的回覆（確認出席或申請改期）記錄在試算表的「面談回覆」工作表。
5. 已發布的通知可以按「取消通知」或「恢復通知」。

### 諮詢回覆
1. 收到 Email 通知後，到試算表「技術諮詢」工作表查看申請內容。
2. 在「諮詢回覆」分頁填入申請編號、狀態與回覆，按「發布回覆」。
   - 要修改時，在下方清單按「修改」再重新發布，網站會以最新一次為準。
3. 新人會在「數位總合辦公室」看到處理狀態與回覆。

## 管理密碼

- **密碼存在哪裡**：只存在「後台更新」表單的驗證規則中，不在網站、GitHub 或 config.js 裡。
- **更換密碼**：修改表單「管理密碼」題目的規則運算式模式即可。
- **忘記密碼**：請表單擁有者打開「後台更新」表單，查看或重設驗證規則。
- **有人離職或密碼外流**：立即更換規則運算式模式。
- **誰看得到密碼**：「後台更新」工作表會記錄送出的密碼，所以只把試算表分享給信任的同仁。

## 資料與隱私

- **網站與設定檔公開**：GitHub Pages 網站與 `config.js` 任何人都看得到。
  - 新人用的三張表單，任何人都能送出資料。發現垃圾資料時，直接在試算表刪除即可。
  - 「後台更新」表單受管理密碼保護，沒有密碼的資料會被拒收。
- **後台資料公開**：「後台資料」是公開發布的工作表，任何知道網址的人都讀得到，所以：
  - 面談通知只寫新人代碼、時間與地點，不要寫姓名、電話或評語。
  - 諮詢回覆只寫處理安排，不要放個人資料。
  - 「操作者名稱」也會被發布，可以用職稱或暱稱。
- **只能給共用者看的工作表**：「進度回報」、「技術諮詢」、「面談回覆」、「後台更新」、「新人名冊」**不可發布**。
- **存在新人瀏覽器的資料**：新人的筆記本、申請紀錄和新人代碼都存在自己的瀏覽器，換電腦或清除瀏覽器資料就會不見。
- **更新會延遲**：發布到網站的資料約有 1–5 分鐘延遲。

## 疑難排解

| 狀況 | 可能原因與處理 |
|---|---|
| 「發布狀態」一直顯示「等待生效」或「尚未生效」 | 管理密碼錯誤（按「更換管理密碼」重新輸入）；「後台資料」公式或發布設定有誤；或「後台更新」表單不接受回應。可以先到「後台更新」工作表查看有沒有新資料：有資料代表密碼正確，問題在「後台資料」的公式或發布設定 |
| 連線狀態顯示「讀取失敗」 | 「後台資料」沒有發布、格式不是 CSV，或公司 Workspace 停用了「發布到網路」。遇到最後一種情況，請改用部門的 Gmail 帳號 |
| 按「送出測試」後試算表沒有新資料 | 表單限制只有公司帳號可以回覆、表單沒有連結到試算表，或預先填入連結的代號填錯（請重新產生 config.js） |
| 錯誤的密碼也發布成功了 | 「管理密碼」題目沒有設成必填，或規則運算式模式不是 `^密碼$` 的完整比對 |
| 更新 GitHub 檔案後網站沒變 | GitHub Pages 最多約 10 分鐘更新，按 Ctrl＋F5；也可以到儲存庫的「Actions」分頁確認部署完成 |
| 新人看不到面談通知 | 確認新人代碼正確，並等 1–5 分鐘。新人換過電腦的話，代碼會不同 |
| 公告沒有出現 | 確認「顯示公告」有勾選並已發布；新人按過「知道了」後，要修改公告的標題或內容才會再次顯示 |

## 已經建立過表單時

新人建立角色時會填寫姓名與員工編號，員工編號是後來新增的欄位。如果表單已經建好，請這樣補上：

1. 在「新人進度回報」、「技術諮詢申請」、「面談回覆」三張表單的**最後面**各新增一題「員工編號」（簡答，不要必填）。
2. 重新取得這三張表單的「預先填入的連結」，在管理者專區的設定小幫手重新產生 `config.js` 並上傳。
3. 「新人名冊」的公式範圍改成 `A2:I`，並在第一列 I 欄補上標題「員工編號」。

沒有補上的話，網站仍可正常運作，只是試算表不會記錄員工編號。

## 舊版設定相容

如果之前已經依舊版說明建立了「網站設定」、「任務內容」、「面談通知」、「諮詢回覆」四個發布工作表，網站仍會讀取它們：

- 設定小幫手中「舊版工作表」的欄位可以沿用這些網址。
- 「後台資料」中已有的內容會優先使用。
- 在管理者專區發布過一次後，網站就會改用後台資料，舊版工作表之後可以停止發布。
